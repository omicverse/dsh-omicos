# 0004 — Revisioned, scoped research memory

Research notes must survive restarts without turning an inferred claim into evidence or exposing a private session note to unrelated sessions. A flat mutable text list cannot represent those distinctions or safely consolidate redundant facts.

The existing project SQLite authority upgrades atomically from schema 1 to schema 2. Current entries remain in `memories`; immutable revisions and operation receipts use separate tables in the same transaction domain. Legacy facts retain their earlier confirmation and timestamp, with explicitly declared legacy provenance. Original JSON imports remain untouched. Unknown application/schema identifiers are rejected. The parent scientific project retains its existing process lock; R and Python read the same authority.

Entries form a topic tree with facts and summaries as leaves. Project and project-local long-term entries can be shared by sessions; session entries require the actual Harness session identity. Unconfirmed proposals created by an Agent are visible only to its origin session and the authenticated owner. Parent visibility also constrains descendants. Long-term currently means durable within one project, not a global cross-project store.

New writes are proposals. Confirmation, withdrawal and moves use an expected revision plus stable operation ID. A repeated operation returns the current readable entry without reapplying an old approval. Direct session promotion and summaries citing session-private sources require an explicit sharing flag. Workbench mutations require owner authentication and CSRF; confirmation has an additional explicit flag. Agent mutations pass the existing Harness tool approval hook and cannot supply an owner identity.

Memory sources pin the referenced entry's revision and digest. Local execution sources identify an actual terminal project receipt, not a scientific validity judgment. Files, citations and user statements remain declared references; no network fetch, file read, upload or inferred validation occurs. Pipeline receipts do not yet resolve through this source kind. The source JSON editor exposes these distinctions.

Confirmation can atomically consolidate a summary and mark its independent original sources superseded, repinning to those new revisions. Original history remains readable. Source changes or withdrawal make dependent summaries ineligible for automatic context. Consolidation of a dependent source set that would immediately invalidate the summary rolls back completely. Withdrawing a topic preserves descendants while making their context ineffective until their hierarchy is valid again.

Only effective confirmed leaves are projected into the scoped Scientist's public `system-prompt/assemble` hook. The actual session ID comes from the Host agent; no second model loop exists. The bounded current snapshot prioritizes session notes, includes evidence identity and omission policy, and marks memory as contextual data rather than instructions. Interpolation is disabled so saved `{{variables}}` remain literal. The section never mounts in unrelated presets. Earlier snapshots may remain in the conversation, so the current policy explicitly requires rereading absent facts before relying on them.

The responsive workbench supports paginated search, topic filtering, proposals, explicit confirmation/sharing/consolidation, withdrawal and immutable history. It refuses stale revisions rather than overwriting another window. Evidence and context budgets are bounded, but project-wide indexing, global memory, automated scientific review and broader dossier search remain future work.

Validation includes native schema-v1 migration, revision/idempotency conflicts, transactional consolidation rollback, private-note isolation, stale-source invalidation, authenticated HTTP routes, the real rc.3 preset loader, and browser coverage of the actual Harness model request plus the standalone editing workflow. Mock model and cloud fixtures do not spend real funds.
