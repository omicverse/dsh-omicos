# 0005 — Figure Studio preserves execution artifacts and review history

Figures must remain attributable to the execution that produced them. A mutable image path or an unversioned caption cannot establish which bytes and explanation a reviewer examined. The workbench therefore curates existing scientific artifacts rather than silently editing their original files.

Each project has a private SQLite Figure Studio database, owned through the existing project runtime lock. Version 1 uses WAL, FULL synchronization, application identity, immutable revision rows, current pointers and stable operation receipts. New saves and assessments commit their current version and immutable history atomically. Writes serialize around asynchronous source verification; stale expected revisions fail rather than overwrite another window. Replayed operations return the current document without repeating an old assessment. Shutdown awaits pending writes before closing the database.

A figure version fixes one project or Pipeline execution artifact, caption, declared method/data references, actual code/output hashes and environment receipt. Sources resolve against authoritative project/Pipeline execution records; callers cannot supply a replacement artifact path or claim a receipt. Both Python and R sources work without starting an interpreter just to read a figure. All source reads are regular files contained within their scientific workspace, bounded to 32 MiB and checked against size and SHA-256. Downloading an old figure version resolves and verifies the original bytes again. Missing/changed originals remain missing/changed; metadata/history are retained and code is never rerun automatically.

Every save resets review to draft. Authenticated human review requires an explicit decision, note and exact current revision; approval verifies the bytes again and records the assessed revision digest. Withdrawal or a request for changes can be recorded even when original bytes are unavailable. Agent tools can read the library or propose a new version through Harness approval, but have no autonomous figure-approval tool. This is a recorded human assessment, not an isolated scientific reviewer or independent validation of citations/data/method claims.

The source catalog pages through all main Python/R receipts and all Pipeline attempts using stable row/attempt/artifact cursors, independently of the recent-run list. The library has search and bounded pagination; history pages 50 revisions at a time. Figure records point to existing bytes and do not copy datasets. Source-catalog metadata does not itself assert that current file bytes still match; opening the document requests a fresh integrity check, and every download verifies again.

Python Matplotlib outputs retain PNG previews and PDF/SVG exports; R keeps its existing PNG/PDF capture. PNG/JPEG can render as raster previews. SVG/PDF are downloadable attachments with `nosniff`, never executable inline browser documents. Notebook local execution output now renders verified PNGs and download links; imported rich output remains unverified and unexecuted. Publication export consists of original artifact bytes plus a version-specific provenance JSON manifest, with explicit limits on evidence coverage.

The workbench keeps OmicOS's restrained scientific palette, with a figure archive beside a larger source/caption/review workspace and side-by-side historical comparison. Dirty edits require preservation/explicit discard, and background refresh cannot replace the editor. The page retains local drafts when visiting the store. Cross-project navigation has the existing project remount behavior; no global image editor, external publication, automated reviewer or collaborative review synchronization is claimed.

Validation covers real Python PNG/PDF/SVG, Pipeline artifacts across restart without execution, immutable assessed captions and reset-to-draft edits, CAS/idempotency, private database permissions, bounded contained source reads, tamper rejection, multi-page catalogs/history, owner/CSRF/confirmation routes and vector download headers. Browser integration runs a Notebook plotting cell, curates and approves its actual output, downloads the provenance manifest, revises/compares/reloads it, and checks mobile layout alongside the existing scientific and store flows.
