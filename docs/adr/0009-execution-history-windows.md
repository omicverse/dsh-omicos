# 0009 — Recent execution windows are not the durable archive

Long-running projects must not send every historical code cell and stdout buffer on each variable refresh. The project ledger remains the complete authority; the live service caches the recent 100 executions plus queued/active/finishing entries and unresolved dirty writes. Public snapshots expose only the recent 100 with total/active/window metadata. Archive eviction is not deletion, permission to rerun, or an inferred failure.

Opening a language namespace recovers all its older queued/running receipts in bounded batches, then loads the recent window. Archived execution IDs and language-scoped operation IDs resolve directly through SQLite. An unchanged old operation still returns its original receipt; changed code/session/generation with that operation is rejected. Old terminal cancellation is harmless, while receipts not owned by the live queue are not falsely canceled. Persistence failure keeps in-memory uncertain outcomes rather than evicting a known failure into a stale durable success. Failure notifications participate in the persistence tail so shutdown can wait for change observers before closing the ledger.

The owner-authenticated `executions` endpoint projects up to 50 bounded summaries using row-ID cursors and optional language/state/code-or-ID filters. Full code/output, environment and artifact metadata remain available through the separate receipt endpoint. Native JSON projections bound transferred fields; no interpreter is launched for archive reads. Summary states are recorded states, not an OS-process liveness assertion. Stable cursors do not promise a globally frozen view during concurrent new executions; totals describe the language's durable archive, not only filtered matches.

The workbench has an explicit history browser, and Notebook cells whose receipts leave the recent window offer on-demand historical result loading. Source edits still invalidate that result. New artifact URLs name both execution and artifact for direct receipt resolution; existing artifact-ID links retain their archive lookup path and byte/containment checks. Pipeline receipt retrieval also resolves an exact archived ID rather than loading a language's complete history. The Agent history tool exposes the same pagination while existing exact-ID status calls keep their semantics.

Legacy complete Notebook downloads remain complete. The ledger scans 25 records at a time through ordinary materialized SQLite pages (avoiding the older Node temporary-statement iterator issue), and HTTP serialization waits for downstream backpressure. The scan pins its initial upper row ID and overlays the live cache; it does not copy the whole archive into a response object. A disconnected client stops the export. Individual running receipts can advance during export: this is history export, not an atomic kernel/dataset snapshot or an automatic reproducible replay. Programmatic `notebook()` retains its explicit all-cells return contract, so callers that choose to materialize it still own that memory cost.

Separate lightweight kernel and memory reads avoid cloning execution buffers just to check Pipeline generations or shared project facts. Metadata schema remains compatible; no existing scientific records are deleted or rewritten merely to shrink a window. Pipeline run-list paging, archive retention/deletion and large project-memory indexing remain separate work, not implied by this change.

Validation uses 250 durable receipts with old unfinished entries outside the recent window, stable old-operation replay, bounded multi-page summaries, full export and language separation. Another fixture queues 110 actual Python increments, verifies all run, and proves replay of the evicted first operation does not increment again. Authenticated HTTP tests retrieve old images/receipts and stream 130 cells without starting a kernel. Browser coverage ages Notebook outputs beyond 110 newer executions, retrieves the old output/image and searches/paginates history without re-executing those cells.
