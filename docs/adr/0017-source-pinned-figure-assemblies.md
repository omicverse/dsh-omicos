# ADR 0017: Source-pinned multi-panel figure assemblies

Status: implemented for original PNG panels and self-contained SVG export. Font-aware PDF, vector/JPEG composition and broader publication conventions remain migration work.

## Model and source identity

A private project schema-1 SQLite journal stores immutable layout revisions, current pointers and actor-bound operation receipts. A layout contains title, caption, page dimensions and 1–16 panels with exact Figure Studio ID/revision, rectangle and literal label. The Host resolves real saved figures and original artifact bytes; it does not accept proposed source metadata/bytes, arbitrary paths or remote image URLs. Snapshots retain each source figure's execution state/code/environment, artifact hash, declared references and historical review. Repeated panels reuse one metadata snapshot but count separately against rendering/export budgets.

Inputs require integer contained rectangles of at least 80×80; page sides are 200–8000 with at most 32 million page pixels. Nonempty labels are unique, single-line, at most 40 characters. Each actual PNG header is checked for format/dimensions and a 25-million-pixel bound; combined panels are limited to 32 MB / 60 million source pixels including repetitions. This is header/identity validation, not an independent PNG decoder or image/scientific analysis. Metadata is limited to 4 MB per record and SVG to 64 MB. Repetition budgets are checked before base64 encoding, so one large source repeated many times cannot construct an unbounded export first. Immutable scalar history/discovery pages are limited to 50; individual historical snapshots are fetched separately.

## Geometry, review and exports

Source PNG byte streams remain exact. SVG images use proportional `xMidYMid meet` placement, reserving 32 layout pixels above a labeled panel; no scientific crop, color transform, resampling or plot regeneration is performed. Page background is white. Labels are literal escaped XML at 22 layout pixels; captions live in SVG description and provenance metadata, not baked into source images. Layouts may intentionally overlap, and typography depends on the viewing software; the preview and human review must inspect label/geometry choices. No automatic journal-layout or scientific-validity assessment is claimed.

Any save/explicit recapture resets review to draft. Only owner/CSRF-protected workbench decisions approve/request changes/withdraw; Agents can read and make approved proposals but cannot review. Approval requires every pinned source to be currently individually approved, with unchanged figure identity and actual original bytes. Source checks are sequential observations, not a global transaction. A later source edit/withdrawal leaves earlier assembly review historical and makes explicit current integrity report `needs-review`. New approval fails until the owner captures/reviews suitable current sources.

SVG export embeds the original PNG data URIs plus the fixed layout, saved source-version snapshots and a separately labeled current-source integrity observation. It does not silently replace old sources with current metadata. Historical export remains possible after metadata/review drift if the original pinned bytes are still verifiable; changed/missing original bytes reject image export. JSON manifest export remains available as a historical record even when images disappear. Both formats include original execution text/paths and may include sensitive source image metadata: no automatic secret redaction, data-inclusive replay bundle or upload/publication occurs.

The SVG emitter creates only fixed svg/title/desc/metadata/rect/g/image/text elements. Every free text/JSON value is XML-escaped, numeric geometry is normalized, and href contains only verified PNG base64. No script, foreignObject, external image/font URL, raw SVG input or user HTML is emitted. The file is served as a nosniff attachment. Workbench preview uses controlled React SVG elements with same-origin hash-verified PNG routes and the same geometry, never injection of exported/untrusted markup. Underlying single-figure vector/PDF/JPEG original exports are unaffected.

## Lifecycle and verification

Assemblies are disposed before their source Figure Studio service; writes drain before closing. Composition, review and export do not start a scientific kernel. Browser drafts preserve edits during discovery/paging, require explicit save, and preview/download the exact saved revision; dirty drafts cannot be reviewed. A source picker and grid arranger prepare layouts while JSON allows exact positioning; recapturing current source revisions is explicit. Search/history and exact-ID opening support records beyond the first page.

Native fixtures cover actor-bound replay, CAS/review resets, authoritative metadata over forged proposals, source drift and disappearance, frozen history/export, geometry/format/byte/pixel limits, repeated-image budget rejection before encoding, bounded discovery/history and restart. Actual Python makes two distinct PNGs; both exact streams and environment/receipt identities appear in one SVG, survive restart without another execution and reject later byte changes. HTTP tests cover owner/CSRF/confirmation, exact-version attachments and historical lookup with no scientific execution or cloud traffic. Real ToolRuntime denies Agent proposals without approval and exposes no assembly-review tool. Browser integration covers real Notebook PNGs, two panels, decoded original previews, human review, SVG byte identity, later source-caption drift and historical review after reload. Final concrete full-suite/browser results are recorded in IMPLEMENTATION_STATUS.md rather than inferred for other platforms.
