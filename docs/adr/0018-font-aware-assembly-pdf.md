# ADR 0018: Font-aware assembly PDF, original attachments and bounded rendering

Status: implemented for static supported <=16-bit PNG panels and static outline TTF/CFF-OTF label fonts. Animated/HDR PNGs, vector/JPEG composition, broader typography and journal publication rules remain explicit migration work.

## Export authority and physical size

The saved assembly is unchanged. A separate owner-authenticated, CSRF-protected, explicitly confirmed POST chooses the exact assembly revision, integer 72–1200 DPI and a font. DPI maps layout pixels to PDF points by `72 / dpi`; it does not increase original image resolution. The renderer retains the proportional image rectangles and label strings, measures label widths and reports actual image-box geometry/effective DPI. Font/physical-size choices are recorded as current export parameters, not automatically covered by an earlier assembly review. New text is not added to scientific pixels. Final journal-specific correctness and complex/bidirectional typography are not automatically assessed.

Provenance-mode one-page PDF has a white page, losslessly drawn supported pixel samples/alpha, an embedded checked label font, exact original PNG file attachments and JSON provenance plus a font-license declaration. PDF image drawing is not the unchanged PNG container: critical PNG sample/palette/alpha streams are decoded into PDF images. Original containers, metadata and their SHA-256 identities are separately retained byte-for-byte as attachments. Nonrendering text/time/physical-resolution metadata is excluded from the decoder input while retained in the original attachment, avoiding irrelevant compressed-text expansion during decoding.

Supported sample/alpha, ICC/sRGB/gAMA/cHRM and nonrendering metadata chunks are accepted (see ADR 0019 for color interpretation). Animated/HDR or unknown presentation-affecting PNG extensions reject instead of silently changing precision/color/orientation. SVG original-source export remains available. Current-source changes stay separately labeled in provenance; old review/source versions are not rewritten. Missing/changed original bytes reject before drawing. Inputs reuse assembly byte/pixel/repetition limits; combined unique PNG/font inputs are at most 44 MB and output at most 64 MB. ADR 0020 adds explicit page-only output without original/source attachments or document metadata. Exact source data files are not attached automatically, and execution text/paths/image metadata are not automatically redacted.

## Fonts, license and format correctness

The default is an unmodified Adobe Source Sans 3 Bold TTF, pinned to an upstream release commit and SHA-256 with the original OFL copyright/license. The font and license are both checksum-verified; Git attributes preserve font bytes and LF license text. This asset keeps its OFL license separately from project GPL code. It is shipped in `runtime/fonts`; no font download/system-font lookup happens during export.

A custom static project TTF/OTF requires a project-relative nonprivate path, expected SHA-256 and a human embedding-license declaration. Containment/private-file checks, regular/nonblocking/nofollow descriptor reads, byte/size/change checks and a 20 MB font bound precede parsing. Static sfnt/table bounds, outline/cmap structure and OS/2 flags are checked; collections, variable/CFF2, bitmap-only or restricted-outline fonts reject. No-subsetting flags preserve full fonts. These checks do not independently establish legal permission. Missing codepoint coverage and labels wider than their panels reject; no silent glyph substitution or clipping is requested.

Independent rendering caught a real pinned-library incompatibility: the CFF subset output could preserve Unicode extraction while Poppler reported an invalid embedded font and substituted/missed visible glyphs. CFF fonts therefore embed in full. A local instance adapter supplies the actual CFF table where the pinned pdf-lib/fontkit interface expects its discriminator, and the whole original OTF stream is explicitly declared `/FontFile3 /Subtype /OpenType`. Parser/encoder objects and global packages are not modified. TTF subsetting remains supported and uses the six-uppercase-letter plus-sign naming tag required by the [PDF font-subset convention](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf), rather than a full-font-looking name. Tests require the CFF font stream to decode to the exact original OTF SHA-256; independent font inspection, text extraction and raster rendering verify the actual result. CJK font fixtures are pinned public Noto Sans CJK files, separate from the shipped font, and are not bundled into the product.

## CPU, lifetime and transport

A trusted Node worker thread renders PDFs with an empty environment and empty Node exec arguments (Host preload/loader flags do not enter the renderer), a 512 MB V8 old-generation limit, 64 MB young-generation limit and 4 MB stack. This is CPU/lifecycle isolation, not an OS/filesystem sandbox or absolute native/RSS memory bound. Only fixed product/library code runs; no scientific/user code is evaluated and no interpreter/model/cloud service starts. A two-export limit is acquired before source/font preparation, not after potentially large input reads. A 45-second worker deadline, request abort and Runtime shutdown terminate the real thread and wait for its exit before settling; preparations are bounded file reads and are cancellation-checked. Unsupported/malformed rendering failures return errors without a completed artifact. Broader remote-filesystem I/O timeout policy remains separate.

The PDF route returns `application/pdf` as an attachment with an export SHA-256 header. The workbench checks the actual download bytes using Web Crypto before creating a file download, offers cancel, and does not retry unknown network results. Only the established pre-dispatch CSRF rejection can refresh/retry the same request. Export is local/pure: no purchase, publication upload, automatic font installation, cached result pretending to be current, or model-side review permission is introduced. Changing the selected assembly revision disposes its pending UI export.

The renderer is a shipped CJS runtime file using exact public pdf-lib/fontkit runtime dependencies. No private Core or Harness dependency is introduced into standalone PDF export. Clean-package smoke runs the renderer against only the installed package/dependencies and original bundled font. Existing scientific execution, SVG export and immutable source history remain separately usable.

## Verification

Native tests parse real PDFs for page size, embedded font dictionaries, original PNG attachment bytes, source/environment provenance and physical/effective DPI. Actual Python-produced distinct PNGs reach PDF through the Runtime with no additional scientific execution. Font path/checksum/private/symlink/embedding-flag/coverage/overflow and PNG precision/profile refusal are exercised. Real CPU-bound worker fixtures demonstrate abort, deadline, shutdown and concurrency rejection before source preparation. A real child Host launched with a rejecting worker preload proves that Node preload flags are not inherited by the renderer. HTTP tests verify owner/CSRF/confirmation, exact revision, MIME and actual body SHA.

CJK tests embed a real pinned static Noto OTF, verify full original font bytes in the PDF's OpenType stream, and preserve Chinese text. CI prepares that checksum-pinned fixture and uses independent Poppler text/raster tools, failing on renderer diagnostics. Local visual inspection confirms the visible Chinese glyphs rather than inferring success from text extraction alone. Browser integration exercises the owner-confirmed PDF workflow and verifies downloaded bytes; full scientific/package/Harness regression results belong in IMPLEMENTATION_STATUS.md. Remote CI, full Windows/Electron deployment and unsupported publication formats are not inferred from these local checks.


### 16-bit sample preservation follow-up

An independent decoder now reconstructs network-order 16-bit grayscale/RGB samples with optional alpha, all five row filters and Adam7 pass placement. The raw color plane and optional 16-bit soft mask are embedded directly as lossless Flate PDF image streams; no 8-bit PNG conversion is involved. Grayscale/RGB transparency keys compare the complete 16-bit samples. The page uses ordinary image XObject operators with unchanged assembly geometry. Unmanaged DeviceGray/DeviceRGB is explicit when there is no color declaration; ADR 0019 adds ICC/sRGB/calibrated color interpretation. Colorimetric appearance is not guaranteed across devices.

The decoder caps the unfiltered input at 96 MB per source, calculates exact pass scanline sizes before bounded inflation, checks compressed consumption/output size and rejects invalid filters/transparency and PNG chunk ordering. It executes inside the existing cancellable/deadline-limited worker. This is not a process-wide memory guarantee. Original PNG attachments remain unchanged. Tests independently encode all color types/filter/pass combinations and compare actual decoded PDF color/alpha bytes, rather than just original attachment hashes. Specification reference: [W3C PNG 3](https://www.w3.org/TR/png-3/), sections 7–11.
